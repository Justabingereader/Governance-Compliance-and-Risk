### ADR-002:  No user-defined routes

Status: Accepted

Context:  The use of a UDR would allow custom redirection of network traffic between subnets or VNets through sending it through an NVA or Firewall. This architecture however makes no use of either a NVA or a firewall which is detailed in ADR-001. 

Decision: I decided to not use UDRs through NVAs because any route table created for the UDR would be decorative rather than functional

Consequences: Absence of a custom network traffic direction to a central storage for traffic filtering and monitoring. The ability to direct traffic coming from spoke technologies to a central hub or gateway is also lost, The ability to send all internet bound traffic through an expressroute or VPN is lost. A UDR with a next hop of none on the global 0.0.0.0/0 address could serve as a real defence in depth control if enabled. Later introduction of Microsoft sentinel is to mitigate the loss of preventive control with detection control.  An expressroute or VPN has not been integrated as part of the architecture of the project, making the functionality provided by the UDR in that aspect non useful to the architecture. It wasn't adopted however because dropping all traffic to 0.0.0.0/0 will break critical operations such as Azure log & analytics, where resources like VMs and applications stop sending logs, metrics and diagnostics to central monitoring services like Microsoft Sentinel, and Azure Storage Accounts in which applications attempting to write blobs or access file shares via a public URL would fail. defaultOutboundaccess: false also serves the same core purpose UDR is to serve in this architecture, making it redundant.

Revision Trigger: If ADR-001 is superseded.
